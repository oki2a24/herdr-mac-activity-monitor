# `src/parsers.rs` ミューテーションテスト試行

## 意図

`cargo-mutants` を小さな範囲で試し、既存の単体テストが解析・計算処理の振る舞いを検出できるか確認する。

## 目標と対象外

- 目標: 通常テストの基準状態を確認し、`src/parsers.rs` の変異結果を調べ、意味のある未検出があれば振る舞いを説明するユニットテストで補う。
- 対象外: `cargo-mutants` をアプリの依存関係に加えること、CIや `make verify` に必須化すること、他モジュールへ対象を拡大すること。

## 制約

- 既存チェックアウトで `codex/mutation-testing-parsers` ブランチを使う。worktreeは作らない。
- 通常の検証はリポジトリの `Makefile` にあるMakeターゲットを使う。
- ツールはプロジェクト外の一時領域に用意し、`Cargo.toml` と `Cargo.lock` は変更しない。

## 手法と選択理由

- `src/parsers.rs` だけに `cargo-mutants` を実行する: Cargoの標準テストに沿い、純粋な解析・計算・書式化処理から小さく始められるため採用する。
- 最初から全モジュールを実行する: OS依存コードや条件付きコンパイルによる結果も同時に調べることになり、初回試行の範囲として広いため採用しない。
- `mutest-rs` を使う: Nightlyツールチェーンが必要で、まず使い勝手を確認する段階では準備が増えるため採用しない。

## 実装者に残された判断

未検出ミュータントごとに変更内容とテストの意図を確認する。等価な変更や重要度の低い変更のためだけにテストを追加せず、必要な振る舞いが未検証の場合に限って `why:` コメント付きのユニットテストを追加する。

## 試行結果

- `make test`: 68件成功。
- `cargo-mutants 27.1.0 --file src/parsers.rs`: 26件を実行し、24件を既存テストが検出、2件はコンパイル不能、未検出とタイムアウトは0件。
- コンパイル不能の2件は `compute_memory` と `parse_vm_stat` を `Ok(Default::default())` に置換する変異で、返却型に `Default` が実装されていないため生成したコードが成立しなかった。
- この対象では追加テストは不要と判断した。結果は `src/parsers.rs` と今回の変異パターンに限られ、他モジュールや別の変異パターンの十分性は示さない。
- ツールと `mutants.out` はプロジェクト外の一時領域に置いた。`Cargo.toml` と `Cargo.lock` は変更していない。

## 後続作業での範囲拡大

この文書は `src/parsers.rs` の初回試行計画と結果を記録する。ここにある「他モジュールへ対象を拡大しない」という判断は初回試行に限ったもの。その後、ミューテーション結果を起点に battery、memory、metrics、processes、TUI、watch、アプリケーション入口へ段階的に対象を広げた。`cargo-mutants` を任意の開発用ツールとし、通常の `make verify` / `make ci` に含めない方針は維持している。
